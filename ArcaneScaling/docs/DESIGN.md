# 设计与实施计划

## 1. 已确定的方向
内容插件定义装备附魔与相关记录；DLL 读取施法者当前装备产生的自定义加成，在合适的效果实例阶段调整 Magnitude/Duration。配置仅负责策略与系数，不成为新增伤害来源。

## 2. 候选处理链（不是已确认的引擎调用顺序）
识别施法者与来源 → 检查支持范围 → 读取装备附魔 → 汇总加成 → 分类效果 → 计算本次缩放 → 写入本次实例 → 继续引擎处理。

必须实验确认：Hook 能否同时覆盖目标效果类型、是否在合适的抗性/perk处理阶段、是否发生重复调用、实例和数据所有权、时长字段单位与类型。不能以“应用阶段”这一名称推断全部交互正确。

## 3. 候选数值模型（待批准）
- E = 符合规则的已装备自定义附魔强度之和。
- M_new = M_current × (1 + E × magnitudePerPoint)。
- D_new = D_current × (1 + E × durationPerPoint)，仅适用于显式允许延长的效果。
- M_current / D_current 是所选 Hook 阶段的输入，不应臆称已包含或尚未包含某项引擎乘区。
- 系数默认值、叠加上限、负值处理、取整和溢出策略均 TBD。
- 零基数默认保持零；不得把无时长效果凭空变成持续效果。

在落地前明确：多槽位/重复装备计数、同装备多效果、动态附魔、双手同物品、防重复扫描、无关附魔忽略方式。先做正确的读取路径，再决定是否缓存；若缓存则必须记录失效条件。

## 4. 效果支持策略
初版采用允许列表，优先验证玩家施放的一种直接伤害法术。持续伤害、范围、多效果、持续施法、治疗、召唤、控制、符文、斗篷、吸取和脚本效果分别评估，不因学派相同就默认支持。
持续时间允许列表与强度允许列表分开；非支持类别保持原状。NPC、卷轴、法杖、能力、附魔触发法术的范围单独决定。

## 5. 内容记录契约
内容制作前建立记录表：类型、EditorID、本地 FormID、用途、引用关系、是否面向正式发布。前缀统一使用 AS_。
ESL 是目标产物；实际记录数量、FormID 分配、主文件依赖与编辑工具约束需要检查，不预填限制数字。
测试装备/配方是否随正式包发布 TBD。内容插件是二进制权威源还是由脚本生成 TBD；须选择一种并给出编辑、diff/导出与重建/校验流程。
发布后避免重编号或变更识别契约；存档升级/卸载风险必须测试和说明，不承诺随意移除安全。

## 6. 失败行为
不支持运行时应由加载检查拒绝或安全禁用，禁止安装未知地址 Hook。内容缺失/记录类型不符时禁用缩放并记录原因。无有效附魔返回原始行为。非法配置使用明确的安全回退并提示，具体策略在配置实现前确定。

## 7. 分阶段交付与退出条件
| 阶段 | 交付 | 退出条件 |
| --- | --- | --- |
| P0 规划 | 规则、背景、环境表、设计和测试计划 | 文档齐备；技术未决事项显式列出 |
| P1 环境与骨架 | 锁定依赖、可复现构建、最小加载 DLL | 目标环境构建成功且独立测试配置能加载、产生版本日志 |
| P2 内容最小闭环 | 最小附魔/效果/测试装备，记录映射表 | 工具检查通过；游戏中可获得、装备和识别 |
| P3 Hook 可行性 | 一个效果类型的可回滚实验 | 证明实例隔离、单次缩放及已测抗性/perk等顺序；不满足则先修改设计 |
| P4 功能实现 | 装备汇总、范围策略、公式、配置 | 纯逻辑测试与初版范围游戏测试通过 |
| P5 发布验证 | 安装包、说明、版本与证据 | 干净环境恢复成功；支持矩阵逐项有证据 |

P2/P3 可按实验需要调整顺序，调整须记录原因。没有通过 P3 就不能宣称与原生处理或第三方全面兼容。
